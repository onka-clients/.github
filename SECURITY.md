# Security policy

## Signaler une vulnérabilité

N'ouvrez pas d'enjeu public pour une vulnérabilité, un secret, des données de client ou une faiblesse d'accès.

Utilisez d'abord le formulaire privé d'onka-clients : https://github.com/onka-clients/.github/security/advisories/new

Si le formulaire n'est pas accessible, écrivez à info@onkalabs.com avec l'objet `Rapport de sécurité`. Ne joignez pas de secret actif ni de données réelles d'un client. Demandez plutôt un canal de transfert protégé.

Incluez le dépôt ou l'origine touchée, le comportement observé, l'impact possible, les étapes minimales de reproduction et une façon de vous joindre.

ONKA vise un accusé de réception dans les trois jours ouvrables, une première évaluation dans les sept jours ouvrables et une mise à jour au moins tous les quatorze jours pendant la correction. Ces délais sont des objectifs de coordination, pas une garantie de résolution.

ONKA ne poursuivra pas une recherche menée de bonne foi qui évite l'accès persistant, l'exfiltration, la destruction, l'interruption de service, l'ingénierie sociale et les effets financiers. Arrêtez le test dès qu'un secret, des données personnelles, des données de client ou un accès non autorisé est confirmé.

Seule la branche par défaut et la version actuellement en production sont maintenues, sauf indication contraire dans le dépôt.

## Report a vulnerability

Do not open a public issue for a vulnerability, secret, client data, or access-control weakness.

Use the onka-clients private reporting form first: https://github.com/onka-clients/.github/security/advisories/new

If the form is unavailable, email info@onkalabs.com with the subject `Security report`. Do not attach an active secret or real client data. Ask for a protected transfer channel instead.

Include the affected repository or origin, observed behavior, possible impact, minimal reproduction steps, and a way to contact you.

ONKA aims to acknowledge a report within three business days, provide an initial assessment within seven business days, and give an update at least every fourteen days while remediation is active. These are coordination targets, not a resolution guarantee.

ONKA will not pursue good-faith research that avoids persistence, exfiltration, destruction, service interruption, social engineering, and financial effects. Stop testing as soon as a secret, personal data, client data, or unauthorized access is confirmed.

Only the default branch and the version currently in production are supported unless the repository says otherwise.
